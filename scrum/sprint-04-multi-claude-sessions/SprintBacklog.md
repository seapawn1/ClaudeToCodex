## 第一部分：Sprint Goal 与 DoD

### Sprint Goal（PO 方向，待团队 Planning 收敛）

> 让 PO 通过同一个 Codex 原始会话，与至少两个可明确辨认的 Claude Code 原始会话持续开展独立交流，无需为了更换交流对象而拆除另一条连接，且每次消息、回复与连接操作都作用于正确目标。

与 Product Goal 的关系：将两个原始会话直接交流的价值扩展到多个协作对象，使多个项目或同项目内的协作可以持续推进。最低可验收规模为一个 Codex、两个 Claude；多个配对共存不自动承诺任意规模、广播或并发吞吐。

### DoD（与 Product Backlog 一致）

**Definition of Outcome Done**

PO 在真实使用场景中亲身体验产品，确认当前 Product Goal 所约定的价值已经实现，并记录体验场景与结论。

**Definition of Output Done**

Increment 已集成到产品中，可通过标准产品入口使用，通过与其声明范围相适应的质量验证，并由 PO 按事先约定的验收标准验收通过。

### 推进与隔离边界

- 先在独立工作区编写原型代码，验证多配对、路由和统一收件；原型阶段保持产品源码、分发副本及已安装插件原状。具体架构和分解由 Developer 决定。
- 使用专用测试 Codex 与两个测试 Claude，隔离工作目录、配置、桥数据及生效 hooks。不得修改日常插件安装、缓存、marketplace、共享配置或在用桥；对话内禁用若可能影响共享配置，不作为默认隔离办法。
- 最小真实检查点覆盖两个配对共存、交错回复不串目标、相近时间来信处理。原型通过后再在开发工作区整合产品代码，并在独立测试安装中验收候选插件；日常安装更新由 PO 另行决定。
- Developer 与 SM 组织环境准备和技术验证；需要 PO 登录、宿主信任、范围取舍或集中体验时，由 SM 报告具体事项。原型验证不计为插件 Increment 已达到 DoD。

### 明确不纳入

- 任意数量会话、跨机器、跨平台、自动启动或终止 Claude 会话。
- 广播、自动选目标、自动重试、送达回执、事务性投递或并发吞吐指标。
- 自动恢复端点或静默替换 / 迁移旧配对；必要的迁移或显式重建须保留证据并明确产品路径。
- PBI-03 的完整投递状态能力、PBI-07 的完整安装维护能力。

不承诺并发吞吐或全局顺序，并不免除两个目标相近时间回复时的明确处理规则，见 S04-11-5。

### PBI-11 验收标准（审阅稿）

以下编号用于逐项验收与证据关联。验收细节待研究后与 PO 明确，可行性由 Developer 评估。

1. **S04-11-1 配对共存**：在声明支持的 Windows 环境中，同一个 Codex 原始会话能显式建立并保留至少两个正在运行的 Claude 原始会话目标。连接 B 不拆除 A；状态入口能辨认各目标、项目上下文、原会话和连接状态。
2. **S04-11-2 目标确定**：新发送有确定的目标，实际对象与用户选择一致。目标名称不存在、有歧义、身份失效或已断开时，操作说明原因与可执行下一步，不猜测、不静默切换。名称只是可读选择依据，不能替代稳定的原会话身份。
3. **S04-11-3 回复归属**：回复和追问沿被回复消息的关联绑定原目标，不随最近一次发送、当前选择或候选排序改变。关联已明确时无需 PO 再手写目标 ID；关联失效或与请求目标冲突时，不能将正文投给其他会话。
4. **S04-11-4 真实交流**：分别与 A、B 完成业务请求、回复、追问和后续回应；A、B 各自在其原始会话收到对应正文，同一个 Codex 原始会话收到两条交流的回复。切到 B 往来后再次回复 A 的旧消息仍正确。完整正文与自动 messageId / pairId / conversationId / replyTo、目标身份、数据位置和时间窗一致，另一目标无对应误投事件。
5. **S04-11-5 来信重叠边界**：两个独立目标可能相近时间向 Codex 回复。Developer 必须定义并验证系统在接纳、等待或拒绝时的可观察行为；已接纳消息不静默覆盖、丢弃、串目标或重复注入，未接纳与送达未知不能混为成功。容量不足或失败时有明确状态和后续动作，不诱导在投递结果未知时盲目重发。最小验收包含真实的重叠来信尝试及相应关联核对，不只演示人工完全串行的两条往返。
6. **S04-11-6 单目标生命周期与隔离**：A 停止、重启、断开、重连或替换时，B 的配对、待收信息、历史证据和实际通信仍可用。操作对象与影响明确；A 的待收和在途消息按约定处置，旧回复不会进入新原会话，数据保留与失败状态可查。
7. **S04-11-7 单目标与接收兼容**：只配置一个目标时，1.0.0 已验证的标准入口、身份校验、原会话收信、空闲唤醒、工作边界及重复抑制不回退。对既有单配对数据提供明确的继续使用、迁移或重建路径，先说明支持范围并保留证据；未经实测的自动升级不作承诺。
8. **S04-11-8 产品化**：改动在 `bridge/` 与 `plugins/claudetocodex/bridge/` 保持一致；相关 skill、状态 / 连接 / 回复文档及回归同步。最终验证由安装后的可追溯候选执行，记录源码、安装内容和宿主环境。

### 共同验收要求

- 收信按接收方原始会话中的完整正文、自动 messageId / pairId / conversationId / replyTo、目标身份、数据目录和时间窗核对。fixture、宿主加载、实际执行与原会话收信分别判定，`submitted:true` 或单条 context-prepared 不等于收信。
- 同一轮真实使用分别记录技术 AC 与 PO DoD，PO 无需手写标记、ID 或环境变量。
