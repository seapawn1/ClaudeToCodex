## 第一部分：Sprint Goal 与 DoD

### Sprint Goal（本次修订提案）

> 让 PO 在日常项目协作中选对当前 Claude 原始会话、读懂双方往来，并通过标准产品入口掌握和显式处理连接，使完整交流和换会话过程无需人工搬运消息或翻查数据文件。

四条 PBI 围绕同一日常使用过程组织。PO 已确认范围；Goal 的最终措辞与交付预测在研究结果和 Developer 评估后共同收敛。

与 Product Goal 的关系：产品价值仍是让原始会话直接交流，将反馈用于需求澄清、评审和行动。一个 Codex 原始会话现已能同时保持多个 Claude 配对；Goal 中的“当前”指本次连接、发送、回复或断开所作用的明确对象，不表示整个产品只有一个有效配对。

本次续接基线为 `main` / `v1.2.0`（`15309b2`）。[Sprint 04 Review](../../docs/scrum-sprint/sprint-04-multi-claude-sessions-review-retro.md) 已交付多配对、每配对待收槽、回复归属与单配对退役；[Sprint 05 Review](../../docs/scrum-sprint/sprint-05-bridge-root-consistency-review-retro.md) 已交付 per-Codex 数据根选择 / 复用、跨根诊断和连续官方投递。安装入口沿用 [Sprint 02 Review](../../docs/scrum-sprint/sprint-02-install-package-release-review.md)，空闲与工作中收信规则见 [原始设计验证](../../docs/ideo-design/cross-session-agent-messaging.md)。历史证据须说明对本次候选的适用性，不能自动替代本 Sprint 验收。

- 自动启动或终止 Claude / Codex 进程、自动恢复、广播、自动重试、送达回执、跨机器或跨平台能力。
- 插件卸载、完整安装维护与未验证的升级兼容承诺，仍由相应产品待办项精化。
- PBI-03 的完整消息投递状态语义；本 Sprint 的摘要仍须诚实区分已知状态与未知，不能把连接存在、领取或 `submitted:true` 表述为原会话收信。

“结束连接”在本审阅稿中指桥接关系的生命周期；若 PO 所指还包括结束宿主进程，须明确新的产品边界后再形成承诺。

### 验收标准（审阅稿）

以下编号用于逐项验收与证据关联。2026-09-14 的基线修正与验收补充仍为审阅稿，须经 Developer 对抗检查、SM 审阅与 PO 检视后定稿；研究可进入 Developer 的 HOW，尚未验证的方案不当作已具备的产品能力。

#### PBI-09：消息可读，原会话接收行为不回退

1. **S03-09-1 呈现结构**：两侧原始入站消息保留可辨认的发送方 / 目标、创建时间、回复关联、完整正文及可执行的完整回复入口。日常呈现可读，不全量倾倒内部 JSON / UUID；完整 messageId 保留在回复入口，其余关联信息可按需查证。PO 可见的正文或可靠原文入口按 S03-09-7 单独检视。
2. **S03-09-2 来源边界**：Claude 侧省略桥自身重复声明的前提，是实际宿主仍可辨认外来来源；Codex 侧保留简短等价声明。对端内容不被提升为 PO 指令或授权。
3. **S03-09-3 唤醒与提示**：唤醒、已处理及没有待收正文等提示可理解，正常收信和重复抑制不被产品文案误报为故障。明确区分正文进入模型上下文、前端是否呈现、未知 / 失败；宿主未暴露的状态不得推定。宿主固定外框与注入内容的可控范围须实测记录，并由 PO 检视实际可读性。
4. **S03-09-4 原会话行为**：两个方向都须验证空闲收信触发下一次模型调用，无需 PO 再输入一条消息推动；工作中收信保持当前模型调用及工具执行完整，并在随后模型调用前提供正文。模型获得消息后自行判断是否回应，不要求自动发送确认回复。
5. **S03-09-5 兼容与防重复**：同一消息不重复注入，已消费唤醒不重复触发业务处理，普通用户输入不被错误抑制。唤醒文本和呈现方案由 Developer 依据宿主实证选择；若改变格式，须明确在途旧格式兼容及解析回归，不能沿用未经验证的格式假设。
6. **S03-09-6 真实往返**：安装后的同一候选在两个原始会话间完成请求、回复、追问、再答；正文和自动关联字段核对一致。此项不能替代空闲与工作边界的独立判据。
7. **S03-09-7 PO 可见与主动报告（补充提案）**：覆盖 Sprint 05 的“答复已进上下文，但 PO 须再次催问”场景。PO 在等待协作答复时，无需额外输入催问，即可从接收正文后的会话输出获知来源、答复内容和回复去向；完整原文可直接读到或经可靠的标准产品入口取得，无需翻查数据文件。原会话入站、前端可见与主动报告分别记录证据，模型自述不能充当收信证明。具体呈现方式与报告时机由短研究检视，不损害 S03-09-4 的模型 / 工具边界，不引入自动确认回信。

#### PBI-10：状态可信，沿用与换配对明确

1. **S03-10-1 状态含义**：标准状态入口默认给出当前 Codex 所属数据根与全部活跃配对的可读摘要。未配对时有明确状态与下一步；已配对时逐项给出创建时间、双侧可辨认身份、端点观察结果、每配对待收槽的无 / 有及消息标识、最近事件摘要。原始结构化信息另有入口。登记存在、进程存在与端点可联系不能相互冒充；无法判断的部分明确未知。保留已有数据根诊断的事实与未知边界，不要求 PO 手写根路径。
2. **S03-10-2 沿用与替换**：重复连接同一原会话身份时明确沿用该配对，并说明名称 / 端点刷新；连接新 Claude 身份时明确新增配对，其他配对继续保持。需要结束旧配对时，明确对象和显式操作，不把“选择另一目标发送”混同为退役或全根重建。名称不是原会话身份的替代，不静默覆盖不同配对。
3. **S03-10-3 归档与重建**：指定配对的退役及后续显式连接可沿标准入口完成，无需 PO 手动浏览、删除数据目录内文件。旧证据保留，归档可追溯且多次操作不覆盖；失败时如实说明实际状态，不能报告成功或丢失原证据。操作不改绑当前 Codex 的数据根、不迁移整根或影响其他活跃配对。待收及在途消息采用 S03-13-3 的统一规则。
4. **S03-10-4 真实场景**：同配对沿用、另一身份新增连接、指定配对退役后显式重连分别验证，相关路径均有真实收发。记录前后的原会话身份、配对和数据根，旧证据可查，并验证另一个已连接目标仍可通信；端点停止和未登记状态也有相应验证依据。

#### PBI-12：从多个候选中选对当前目标

1. **S03-12-1 可辨认**：选择连接和发送前，用户能辨认当前目标的会话名称、项目上下文与原会话依据；同名、近似名或同项目会话仍有足够的区分信息。完整技术标识可按需查证，不要求 PO 手写 ID。
2. **S03-12-2 误选可纠正**：目标不存在、名称有歧义或可见信息不足时，不猜测、不向任一候选发送探测性业务正文。用户能在实际发送前发现错误选择并取消或改选；是否需要额外确认、如何呈现，由短研究验证，不预设确认按钮或每条消息都重复确认。
3. **S03-12-3 身份绑定**：实际投递对象与用户已明确选择的原始会话一致，不能因候选排序、同名新会话、端点重启或后续选择变化而静默改投。回复沿被回复消息的关联查找原目标；旧关联失效时明确失败并给出下一步。
4. **S03-12-4 场景验证**：至少两个真实 Claude 原始会话参与，覆盖连接前候选和多配对共存时的发送目标辨识，包含同名 / 同项目等易混淆场景及发送前纠正。正确原会话收到完整正文，其他候选在对应时间窗内无该消息的入站事件。名称、时间或活跃线索不足以区分时须明确选择，不以启发式猜测身份；歧义、失效与身份变化分支有相应回归证据。

#### PBI-13：状态与连接操作可直接使用

1. **S03-13-1 操作入口**：用户通过安装后的标准产品入口找到状态与连接操作，无需记忆底层脚本路径或翻找数据目录。插件自身的可观察启用 / 加载 / 授权状态与桥配对 / 端点状态分清；宿主未暴露的信息明确未知，不能用“已安装”推定“可通信”。
2. **S03-13-2 显式断开与重连**：操作前可辨认指定配对、影响和数据保留方式，操作后能查到实际结果；断开成功后旧连接不再接受新的 send / reply，重复断开给出一致且可理解的结果，后续连接按显式操作建立。其他配对继续可用；断开桥接关系不隐含终止宿主进程、卸载插件或关闭整个 Codex 数据根。
3. **S03-13-3 待收与在途边界**：以现有 `retire` 约定为研究与验收基线：指定配对注册身份归档，待收正文和历史证据保留原位；已接纳的在途消息仍按原存档身份处理，新 send / reply 被拒绝，其他配对不受影响。须让用户理解操作与收信交错时哪些动作生效、已有消息仍可能到达哪里，以及如何继续。已进入上下文的内容不能承诺撤回，旧消息不能在重连后误投新目标；操作未完成或失败须如实说明。若研究建议改动该约定或增加软断开状态，须先呈现对用户、在途消息和既有兼容性的影响，经协商后再改变承诺。
4. **S03-13-4 真实操作**：在标准入口验证查状态、正常断开、重复断开、断开后发送 / 回复的处理、显式重新连接及其真实双向交流。带待收消息的断开 / 重连按 S03-13-3 的规则验证，同时检视另一个目标继续可用、历史证据可查及失败状态诚实。与 S03-10-4 共享场景及证据，逐项保留 AC 映射。
