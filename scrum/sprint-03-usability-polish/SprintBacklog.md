## 第一部分：Sprint Goal 与 DoD

### Sprint Goal（本次修订提案）

> 让 PO 在日常项目协作中选对当前 Claude 原始会话、读懂双方往来，并通过标准产品入口掌握和显式处理连接，使完整交流和换会话过程无需人工搬运消息或翻查数据文件。

四条 PBI 围绕同一日常使用过程组织。PO 已确认范围；Goal 的最终措辞与交付预测在研究结果和 Developer 评估后共同收敛。

与 Product Goal 的关系：产品价值仍是让两个原始会话直接交流，将反馈用于需求澄清、评审和行动。同一时刻仍只保持一个有效配对；存在多个可选 Claude 会话，不等于已经支持多个配对共存。

已交付基线见 [Sprint 02 Review](../../docs/scrum-sprint/sprint-02-install-package-release-review.md)，空闲与工作中收信规则见 [原始设计验证](../../docs/ideo-design/cross-session-agent-messaging.md)。这些记录不替代本 Sprint 候选的验收。

### DoD（与 Product Backlog 一致）

**Definition of Outcome Done**

PO 在真实使用场景中亲身体验产品，确认当前 Product Goal 所约定的价值已经实现，并记录体验场景与结论。

**Definition of Output Done**

Increment 已集成到产品中，可通过标准产品入口使用，通过与其声明范围相适应的质量验证，并由 PO 按事先约定的验收标准验收通过。

### 验收标准（审阅稿）

以下编号用于逐项验收与证据关联。验收细节待研究后与 PO 明确，可行性由 Developer 评估。

#### PBI-09：消息可读，原会话接收行为不回退

1. **S03-09-1 呈现结构**：两侧消息保留发送方、创建时间和回复标识组成的可读头行、完整正文及可执行的完整回复入口。日常呈现不全量倾倒内部 JSON / UUID；完整 messageId 保留在回复入口，其余关联信息可按需查证。
2. **S03-09-2 来源边界**：Claude 侧省略桥自身重复声明的前提，是实际宿主仍可辨认外来来源；Codex 侧保留简短等价声明。对端内容不被提升为 PO 指令或授权。
3. **S03-09-3 唤醒与提示**：唤醒、已处理及没有待收正文等提示可理解，正常收信和重复抑制不被产品文案误报为故障。宿主固定外框的可控范围须实测记录，并由 PO 检视实际可读性。
4. **S03-09-4 原会话行为**：两个方向都须验证空闲收信触发下一次模型调用，无需 PO 再输入一条消息推动；工作中收信保持当前模型调用及工具执行完整，并在随后模型调用前提供正文。模型获得消息后自行判断是否回应，不要求自动发送确认回复。
5. **S03-09-5 兼容与防重复**：同一消息不重复注入，已消费唤醒不重复触发业务处理，普通用户输入不被错误抑制。唤醒文本和呈现方案由 Developer 依据宿主实证选择；若改变格式，须明确在途旧格式兼容及解析回归，不能沿用未经验证的格式假设。
6. **S03-09-6 真实往返**：安装后的同一候选在两个原始会话间完成请求、回复、追问、再答；正文和自动关联字段核对一致。此项不能替代空闲与工作边界的独立判据。

#### PBI-10：状态可信，沿用与换配对明确

1. **S03-10-1 状态含义**：标准状态入口默认给出可读摘要。未配对时有明确状态与下一步；已配对时含配对创建时间、双侧可辨认身份、端点观察结果、Codex 待收单槽的无 / 有及消息标识、最近事件摘要。原始结构化信息另有入口。登记存在、进程存在与端点可联系不能相互冒充；无法判断的部分明确未知。
2. **S03-10-2 沿用与替换**：重复连接同一有效配对时明确沿用；请求不同会话或需要更新端点时说明当前与请求目标及后续动作。名称不是原会话身份的替代，不静默覆盖不同配对。
3. **S03-10-3 归档与重建**：换配对可沿标准入口和明确操作完成，无需 PO 手动浏览、删除数据目录内文件。旧证据保留，归档可追溯且多次操作不覆盖；归档或重建失败时如实说明实际状态，不能报告成功或丢失原证据。待收及在途消息采用 S03-13-3 的统一规则。
4. **S03-10-4 真实场景**：同配对沿用、换会话重建分别验证，每轮均有真实收发。记录重建前后的身份、配对和数据位置，旧证据从保留位置可查；端点停止和未登记状态也有相应验证依据。

#### PBI-12：从多个候选中选对当前目标

1. **S03-12-1 可辨认**：选择连接和发送前，用户能辨认当前目标的会话名称、项目上下文与原会话依据；同名、近似名或同项目会话仍有足够的区分信息。完整技术标识可按需查证，不要求 PO 手写 ID。
2. **S03-12-2 误选可纠正**：目标不存在、名称有歧义或可见信息不足时，不猜测、不向任一候选发送探测性业务正文。用户能在实际发送前发现错误选择并取消或改选；是否需要额外确认、如何呈现，由短研究验证，不预设确认按钮或每条消息都重复确认。
3. **S03-12-3 身份绑定**：实际投递对象与用户已明确选择的原始会话一致，不能因候选排序、同名新会话、端点重启或后续选择变化而静默改投。回复沿被回复消息的关联查找原目标；旧关联失效时明确失败并给出下一步。
4. **S03-12-4 场景验证**：至少两个真实 Claude 候选参与辨识验证，当前只保持一个有效配对。覆盖易混淆选择及发送前纠正；正确原会话收到完整正文，其他候选在对应时间窗内无该消息的入站事件。歧义、失效与身份变化分支有相应回归证据。

#### PBI-13：状态与连接操作可直接使用

1. **S03-13-1 操作入口**：用户通过安装后的标准产品入口找到状态与连接操作，无需记忆底层脚本路径或翻找数据目录。插件自身的可观察启用 / 加载 / 授权状态与桥配对 / 端点状态分清；宿主未暴露的信息明确未知，不能用“已安装”推定“可通信”。
2. **S03-13-2 显式断开与重连**：操作前可辨认对象、影响和数据保留方式，操作后能查到实际结果；断开成功后旧连接不再接受新的 send / reply，重复断开给出一致且可理解的结果，后续连接按显式操作建立。断开桥接关系不隐含终止宿主进程或卸载插件。
3. **S03-13-3 待收与在途边界**：研究须明确断开、换配对与消息处理交错时哪些动作生效、哪些被拒绝、已有消息停留在哪里，以及如何继续。已进入原会话上下文的内容不能承诺撤回；待收正文和历史证据不能静默丢失，旧消息不能在重连后误投给新目标。产品须能如实解释操作未完成或失败的状态。
4. **S03-13-4 真实操作**：在标准入口验证查状态、正常断开、重复断开、断开后发送 / 回复的处理、显式重新连接及其真实双向交流。带待收消息的断开 / 换配对按研究选定规则验证，历史证据和失败路径可查。

### 共同验收要求

- `bridge/` 与 `plugins/claudetocodex/bridge/` 保持一致，产品 skill、使用说明及相关回归同步；真实验证经安装后的标准产品入口执行。
- 收信按接收方原始会话中的完整正文、自动 messageId / pairId / conversationId / replyTo、数据目录和时间窗核对。fixture、宿主加载、实际执行与原会话收信分别判定，`submitted:true` 或单条 context-prepared 不等于收信。
- 同一轮真实使用分别记录技术 AC 与 PO DoD，PO 无需手写标记、ID 或环境变量。
