# W11 PO 端到端体验轮脚本（预置稿，待 W10 缺口裁定后启用）

**给 PO 的话：接下来全部像平时一样用，不需要记任何命令。你在自己的终端里操作，遇到问题就照平时报障的方式说一声。我在旁边记录证据。**

## 准备（我来，你不用动）

- R2 home 的 Codex 会话与一个全新 Claude 会话已由我拉起（tmux 窗口名届时告诉你）
- 你只需在 Codex 会话首次启动时按提示信任 hooks（如果你选了补 Windows 冒烟，那边同样一次）

## 你的体验流程（约 20–30 分钟，可随时中断休息）

1. **真实需求澄清**：把一件你**今天真实想问/想办的小事**直接告诉 Codex 会话（例：让它查一下某个文件、解释一段代码、做个小决定）。中途若需要另一个视角，对它说「问一下 Claude」。
2. **两目标交错追问**：连接第二个 Claude 会话后，先问 A 一半，转头问 B，再回到 A 追问——故意交叉，看消息会不会串。
3. **回复入口体验**：收到 Claude 来信时，直接用它消息里给的回复入口答复（复制运行即可），不要手打命令。
4. **授权体验**：体验一次 Claude 侧接收策略（crossSessionInbound）的实际感受——若你把策略设回默认暂存，会看到等待批准的样子（可选，改回 accept 即可）。
5. **自由使用 10 分钟**：当它不存在，正常干活。任何不顺手的地方直接说出来——那就是产品要改的地方。

## 我在做什么

- 全程只读记录：两侧会话事件文件、桥事件流水、时间点
- 不替你操作、不代你发消息；你说的每句话都是你自己的
- 体验完我出一份「体验轮证据＋AC 对照」给你确认

## 判定口径（与 SMOKE 一致）

- 你看到消息到达并可回复＝到达；模型自述不算
- 你实际完成了想办的事＝体验通过；测试通过≠体验通过
