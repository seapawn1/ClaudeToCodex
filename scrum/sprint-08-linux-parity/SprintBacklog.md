### PBI-16：Linux 原始会话双向通信与到达体验

**用户故事**：作为在 Linux 中工作的 PO，我希望 Codex 与 Claude Code 在各自原始会话中直接交流、回复和追问，以便继续协作，无需人工传话。

承接 PBI-01 / PBI-09 的 Linux 适配。

1. **S08-16-1 双向往返**：分别由 Codex、Claude 主动发起至少一轮请求、回复、追问、再答。每轮始终在选定的两个原始会话中完成，正文与 message / pair / conversation / reply 关联可自动核对；副本或中继代答不计通过。合法范围内的中文、多行与含引号正文，在既有 trim 规则后完整到达；`--body` 与 `--body-file` 两个现有入口均可用。
2. **S08-16-2 收信时机**：两个方向分别覆盖空闲、正在生成、正在执行工具三种状态。在已完成必要信任、接收策略允许的前提下，空闲到达自动触发原会话处理；忙碌到达不抢占当前生成或工具，正文在约定的随后首次模型调用前进入上下文，原任务可以尚未完成。以原始事件核对到达、当前工作结束、注入及续接时序，不能仅凭模型自述判断不中断。
3. **S08-16-3 到达体验**：Claude 来信保有来源、完整正文和尾部标记的可读排队文本，hook 提供指向实际安装位置的 Linux 可执行回复入口，正文不重复注入；保留外来内容并非 PO 指令的来源边界。PO 在真实讨论中能理解答复、辨认来源并继续追问，无需额外催问复述或翻查数据文件；排队状态不被误报为故障，不要求改变现有前端呈现方式。
4. **S08-16-4 兼容与失败边界**：正文 trim 后 1..2000 字符，空白或超限按既有规则拒绝；同轮双 hook 为 noop、跨轮重复抑制、旧单行 wake、普通非桥提示及正文内跨 pair 伪造标记均有回归，保持堆叠 wake 的现有防御语义。错误会话身份不得误投；发送失败保留证据并提示核对实际状态，不自动重试，回执保持 `unverified`，不把提交或通道写入当作收信。

### PBI-17：Linux 多会话协作与持续使用

**用户故事**：作为同时与多个 Claude 会话协作的 PO，我希望在 Linux 中按名称连接和切换目标，并在后续使用中保持正确的连接与回复关系，以便持续开展多方讨论。

承接 PBI-11 / PBI-14 / PBI-15 的 Linux 适配。

1. **S08-17-1 多目标协作**：同一 Codex 原始会话按名称连接至少两个 Claude 原始会话 A / B，连接 B 后 A 仍可通信；发给 A 的消息只有 A 收到，往来 B 后回复 A 的旧消息仍归 A。名称不存在或歧义时列出可辨认候选并拒绝猜测；恰一目标可省略名称，多目标省略名称则明确拒绝，保留现有单目标入口。
2. **S08-17-2 自动数据根**：覆盖默认根空闲、已属当前 Codex、已属其他 Codex，以及同一原会话完全退出后 resume；自动选择或复用原根与配对，旧消息和证据保留，不改绑、不合并。CLI 与 hooks 服务同一根；多 Codex 并发首连不丢索引，同身份竞争不产生重复绑定，不可读索引不被静默覆盖。自动路径验证不预设 `CTC_BRIDGE_DIR`；显式隔离覆盖另行验证其最高优先且不污染索引。PO 不手写上述路径、ID 或环境变量。
3. **S08-17-3 连续与相近来信**：至少两个 pair 各自连续完成至少两条 Claude→Codex 回复，每条完整正文进入 Codex 原始会话并释放 pending，下一条不被首条永久阻塞。两个目标相近来信各自保留、逐事件处理；同目标已有待收时再次发送按既有单槽规则拒绝、不覆盖，另一目标继续可用。重复处理和相近来信的实际时序留证，不据此承诺任意规模、吞吐或全局顺序。
4. **S08-17-4 日常状态与生命周期**：现有 `status` 可核对服务根、全部配对、双侧身份、项目、待收和最近事件；端点文件存在不冒充存活，跨根及未领取诊断区分事实与未知。同身份连接刷新端点 / 名称，新身份新增配对；失效端点报错而不改投。显式退役指定配对后拒绝其新发送 / 回复，历史证据与已接纳在途消息保留原归属；显式重建不使旧回复入口指向新配对，另一目标持续可用。保留 legacy `pair.json` 可见与同身份沿用能力；本项不增加状态 UI 或自动恢复。

### PBI-18：Linux 版本安装、分发与使用支持

**用户故事**：作为 Linux 用户，我希望取得一个有明确版本和使用说明的 ClaudeToCodex 插件，按标准入口完成安装和必要授权，即可使用完整协作能力。

承接 PBI-05 / PBI-08 的 Linux 适配，以及 PBI-02 / 06 / 07 的下述切片。

1. **S08-18-1 标准安装**：在具备声明前置依赖的干净、隔离 WSL2 用户配置与桥数据环境中，经 marketplace / plugin 标准入口安装固定来源候选，完成必要授权后按名称建联并真实往返。产品运行不依赖 Windows 程序、开发工作区配置或手改安装缓存；记录实际 Linux 运行时与 CLI 版本，避免 PATH 上 Windows 程序被当作 Linux 前置。安装入口支持日常项目使用，Node 的安装方法不在此预设。
2. **S08-18-2 启用与入口一致**：Claude 侧无需额外桥插件或手动端点登记；skill、三类 hooks、CLI 与回复指引均来自该安装候选，隔离 Codex home 的回复也回到正确宿主。保留其他工具配置，必要信任与接收策略不被产品代改。凭据不出现在产品正文、普通输出、错误日志或发布包；Linux 凭据访问方式及保护限制由 Developer 在 HOW 说明并经审阅，不把其自动宣称为 DPAPI 等价保证。
3. **S08-18-3 随版使用支持与兼容入口**：随版提供可执行的 Linux 获取、前置、安装、授权 / 重载、首轮通信、状态、显式退役 / 重连及排障说明；覆盖 Node / PATH 缺口、端点失效、名称歧义、根不一致与 pending 未领取。现有低层 `install` / `register` / `pair` / `sessions` 保持可用：`sessions` 能列出可选会话；`register` 产出的 Linux 端点可由 `pair` 引用，并经 `send` / `reply` 在选定原会话完成真实双向往返。重复 `install` 不累积产品注册或破坏其他工具配置；普通用户仍走按名自动建联。已有插件移除 / 重装说明明确数据保留和重新信任条件，文档不承诺未经验证的维护增强、跨版本升级或 Windows 数据迁移。若后续方案要求收缩兼容入口，须先与 PO 协商调整本 AC，不能仅修改随版说明即视为履约。
4. **S08-18-4 版本交付证据**：提供符合既有分发方式的插件候选、来源 commit、版本元数据、逐文件 manifest 与整包校验值；安装缓存关键内容与候选一致，双树同步，包内无会话凭据、配对或消息数据。PBI-16 / 17 及本项在最终安装候选取得对应证据；产品说明、skill、安装 / 使用 / SMOKE 与发布说明同步声明版本、WSL2 实测范围和原生 Linux 未实机验证状态。Windows 既有功能按变更影响完成回归；构建工具和具体实现由 Developer 决定，公开发布仍由 PO 决策。
