### 验收标准（拆分转移稿，待 Planning 精化）

1. **S06-10-1 状态含义**：标准状态入口默认给出当前 Codex 所属数据根与全部活跃配对的可读摘要。未配对时有明确状态与下一步；已配对时逐项给出创建时间、双侧可辨认身份、端点观察结果、每配对待收槽的无 / 有及消息标识、最近事件摘要。原始结构化信息另有入口。登记存在、进程存在与端点可联系不能相互冒充；无法判断的部分明确未知。须覆盖退役后仍有残留待收的可查状态。
2. **S06-10-2 沿用与替换**：重复连接同一原会话身份时明确沿用该配对，并说明名称 / 端点刷新；连接新 Claude 身份时明确新增配对，其他配对继续保持。需要结束旧配对时，明确对象和显式操作，不把选择另一目标发送混同为退役或全根重建。
3. **S06-10-3 归档与重建**：指定配对的退役及后续显式连接可沿标准入口完成，无需 PO 手动浏览或删除数据目录内文件。旧证据保留，归档可追溯且多次操作不覆盖；失败时如实说明实际状态。操作不改绑当前 Codex 的数据根、不迁移整根或影响其他活跃配对。
4. **S06-10-4 真实场景**：同配对沿用、另一身份新增连接、指定配对退役后显式重连分别验证，相关路径均有真实收发。记录前后的原会话身份、配对和数据根，旧证据可查，并验证另一个已连接目标仍可通信。
5. **S06-13-1 操作入口**：用户通过安装后的标准产品入口找到状态与连接操作。插件自身的可观察启用 / 加载 / 授权状态与桥配对 / 端点状态分清；宿主未暴露的信息明确未知。
6. **S06-13-2 显式断开与重连**：操作前可辨认指定配对、影响和数据保留方式，操作后能查到实际结果；断开成功后旧连接不再接受新的 send / reply，重复断开给出一致且可理解的结果，后续连接按显式操作建立。其他配对继续可用；断开桥接关系不隐含终止宿主进程、卸载插件或关闭整个数据根。
7. **S06-13-3 待收与在途边界**：以现有 `retire` 约定为研究与验收基线：指定配对注册身份归档，待收正文和历史证据保留原位；已接纳的在途消息仍按原存档身份处理，新 send / reply 被拒绝，其他配对不受影响。须让用户理解操作与收信交错时哪些动作生效、已有消息仍可能到达哪里，以及如何继续。若研究建议改动约定或增加软断开状态，须先呈现影响并协商。
8. **S06-13-4 真实操作**：在标准入口验证查状态、正常断开、重复断开、断开后发送 / 回复的处理、显式重新连接及其真实双向交流。带待收消息的断开 / 重连按统一规则验证，同时检视另一个目标继续可用、历史证据可查及失败状态诚实。

### Planning 前置问题

- 用场景串演收集 PO 在发送后、重启后、断开前和起疑时会问哪些状态问题，再定默认摘要内容。
- 与 PO 明确“重连续聊”是否属于期望体验；现有重连会产生新 pairId，旧回复入口失效但历史证据可查。
- 确定退役后残留待收在状态摘要中的呈现归属和可查入口。
